# 审计与告警网络转发

转发与平台审计分别处理。检索请求审计与告警持久化后，分别尝试提交同一单线程有界队列；转发失败不会撤销告警，也不会阻塞检索等待网络连接。默认队列容量 256，满时拒绝新消息并计数，不使用业务线程代发。

## 配置

沿用 vacp.syslog.enabled、host、port、protocol（UDP 或 TCP）。新增可选项：

| 配置 | 默认值 | 范围/含义 |
| --- | --- | --- |
| queue-capacity | 256 | 1—10000，等待队列容量 |
| timeout-ms | 1000 | 100—10000，TCP 连接及写入共同期限；DNS 解析在独立发送线程执行 |
| include-query | false | 默认只发审计与告警摘要；仅经授权且接收端处于允许的数据边界内时才开启正文 |

配置无效时停止转发并报告状态，不回退到其他协议。启动后配置变更需要重启平台后端。默认消息不含查询正文、告警原因或处理备注，保留告警和来源审计编号以便在平台内追溯。正文明确启用后，长内容会截短或省略并附标记；消息正文采用 UTF-8，整体不超过 1024 字节，控制字符不会形成额外日志行。严重、高危、中危、低危映射 local0 的 critical、error、warning、informational。

## 状态与接收验证

GET /system/behaviorAlert/forwarding/status 由后台访问边界及告警列表权限共同保护；页面可刷新本次进程的发送、失败、未发送和待发送计数。重启后计数归零，不作为持久审计替代品。未发送包括队列满、配置无效及关闭时尚未发送的消息。已发送表示本机网络写入完成，UDP 无接收确认，TCP 完成写入也不等于接收端落盘。

验证接收需在受控接收端检查实际数据报或 TCP 行内容。TCP 延续换行分帧，所有用户字段的换行已清理。转发使用 RFC3164 风格报文，保留原协议兼容性；此功能不宣称已满足某项国家标准或提供加密审计链路。目标地址、网络隔离、接收端保存及访问控制须按交付环境配置。

队列位于内存中，进程异常退出或队列溢出可能无法转发；平台数据库中的告警仍为原始记录。本批不实现持久外发队列、自动补发或接收端确认协议，若验收要求不丢失外发记录，需另行落实。

参考：RFC3164 https://www.rfc-editor.org/rfc/rfc3164 与 RFC6587 https://www.rfc-editor.org/rfc/rfc6587。

## 检索审计导出

审计页面保留 Excel 导出，另提供 Syslog 摘要导出，覆盖筛选范围内的正常、拒绝及执行失败记录，不受页面分页限制。`/system/log/syslog` 使用审计导出权限保护；每次最多 2000 条，超限明确拒绝并要求缩小范围，不截断后冒充完整导出。空结果导出为空文件。导出在当前账号请求内生成，不建立可匿名下载的静态文件。

检索摘要使用 `VACP-RAG-REQUEST` 标识，记录审计编号、人员编号、账号、准入结果、执行状态、通过与拦截数量、风险分数及耗时。网络外发沿用 `include-query` 配置，默认不含查询正文；页面 Syslog 导出始终使用摘要。原始审计及完整正文仍在平台数据库与受控 Excel 导出中。告警使用独立标识和来源审计编号，避免将一次请求的告警当作新的请求审计。两类消息共享通道计数。
