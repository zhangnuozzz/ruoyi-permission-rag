# IP 访问控制部署说明

## 规则含义

只支持单个 IPv4 或 IPv6 地址，不支持主机名、端口、网段和通配符。新增和编辑在服务端校验并统一地址表示。仅启用记录参与判定。

同一来源同时命中启用白名单和黑名单时，白名单优先。白名单只跳过 IP 黑名单，不跳过登录、静态攻击规则、人员状态、访问时段、密级、知悉用户组或附加策略。回环地址同样检查，不存在隐式本机豁免。不要将当前管理来源误加入黑名单；必要时先保留可信管理地址的白名单。

前置过滤器、MVC 和检索上下文使用同一服务；同一 HTTP 请求的前置和 MVC 检查复用结果。规则查询异常返回 503，不放行业务；拦截日志写入失败会记录应用日志，不改变拦截结果。

## 直连与代理

默认按连接对端地址识别来源，忽略客户端自带的 X-Forwarded-For、X-Real-IP、Proxy-Client-IP 等头。不要开启额外的自动转发头解析器，否则连接对端可能在本规则前被改写。

经反向代理部署时，在平台后端配置实际可信代理的直连 IP，例如代理确实与后端同机时：

```yaml
security:
  trusted-proxies: 127.0.0.1,::1
```

也可设置对应环境变量 SECURITY_TRUSTED_PROXIES。该项只接受逗号分隔的 IP 字面地址；空值表示不信任代理。应按实际部署填写，不能配置任意客户端网段。

代理必须覆盖不可信客户端自带的转发链。当前开发代理会将 X-Forwarded-For 重设为实际连接客户端地址。Nginx 单层代理可使用：

```nginx
proxy_set_header X-Forwarded-For $remote_addr;
```

多层代理应先由入口覆盖伪造头，再由受信任的内层代理追加其连接对端；后端从右向左剥离已登记代理，取第一个不可信节点作为客户端。畸形或过长链拒绝，不能退回可信代理地址当作最终来源。

同时用防火墙或监听范围限制后端入口，避免客户端绕过反向代理。转发链配置不是文档授权配置。

## 上线核对

1. 确认访问日志的来源与实际客户端一致，分别核对直连和代理入口；未登记代理时只会看到连接对端，不能宣称已按最终客户端拦截。
2. 用独立测试来源验证正常、仅黑、仅白、同址黑白、停用规则及伪造转发头；不得用生产管理员唯一来源做封禁试验。
3. 白名单来源仍应无法越过文档密级和知悉范围，也不得跨账号下载导出文件。
4. 验证异常响应、拦截日志和规则恢复；生产规则改动应留有可用的恢复通道。

本文件是部署条件与验收步骤，不代表已经完成真实网络环境验收。当前本地专项隔离测试、真实平台页面回验及后续网络实测分别记录。
