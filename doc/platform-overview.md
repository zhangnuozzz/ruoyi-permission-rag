# 平台功能与业务逻辑

本平台负责知识访问的身份、权限、文档标签、安全检索、审计与处置。管理人员配置安全规则，普通用户在独立门户查询知识、上传文件；最终是否返回某份文档，由服务端按当前人员、文档及策略状态判断。

## 一、用一个场景讲清权限

张三的人员密级是“秘密”，同时属于“研发一组”和“项目A组”。

| 文档 | 张三的基础资格 | 解释 |
| --- | --- | --- |
| 公开的产品资料 | 满足 | 无人员密级和知悉组门槛 |
| 内部的工作手册 | 满足 | 人员密级达到内部级 |
| 秘密、归属项目A组的方案 | 满足 | 密级足够，且属于该文档的唯一知悉组 |
| 秘密、归属项目B组的方案 | 不满足 | 不属于项目B组，即使密级足够也不能访问 |
| 机密、归属项目A组的材料 | 不满足 | 属于项目A组，但人员密级不足 |

“满足基础资格”还须通过账号状态、知识访问状态、个人时间窗口、文档状态及已生效的附加限制。公开文档也须走合法登录和请求校验，不代表允许绕过系统匿名读取。

用户组只确定知悉范围，不自动提升人员密级。部门用于组织管理，平台角色决定管理功能入口；它们不直接替代文档授权。

## 二、各部分分别解决什么问题

### 首页

展示人员、文档、请求和待处理告警数量，查看请求趋势、准入结果与最近活动。统计来自平台业务表；“请求获准”是允许执行检索，不表示所有候选文档都能返回。文档拦截数量应结合审计明细查看。

介绍时可说：“首页用于掌握运行和安全态势，具体原因可继续下钻到审计及告警。”

### 安全检索中心

| 页面 | 操作内容 | 与其他模块的联系 |
| --- | --- | --- |
| RAG安全检索 | 输入问题，执行受控检索，查看结果与管理诊断 | 使用身份权限中心的人员、组和策略，结果进入审计 |
| RAG文件入库 | 上传并检查原文件、入库记录与切块情况 | 上传人由登录身份确定，文档标签参与后续检索 |
| 文档权限标签 | 管理文档编号、密级、唯一知悉组及启停状态 | 文档实际返回前再次校验当前标签 |

检索前，平台把当前人员密级、有效知悉组和附加限制转成向量查询约束；收到候选后，再按平台数据库中的当前标签逐条复核。两次判断的目标相同：让不符合权限的正文不能到达普通用户。

上传成功、正文识别正确、向量写入成功和能正确检索，是不同的检查环节，不能只看到文件列表就认定全部成功。当前停用文档会阻止检索返回，但不会物理删除原件与向量。

### 身份权限中心

| 页面 | 维护对象 | 业务含义 |
| --- | --- | --- |
| 人员权限管理 | 人员基础信息、组织归属、角色、密级、知识访问状态、时间窗口和所属组 | 定义“这个人是谁、具备什么基础资格” |
| 用户组管理 | 用户组编码、负责人、成员和组状态 | 定义“这个人知道哪些范围的资料” |
| 访问策略管理 | 可执行的附加限制、适用对象和版本 | 定义“符合基础资格后，还要满足什么条件” |
| 权限上下文 | 当前身份、密级、有效组、时间与策略摘要 | 解释当前请求使用哪些安全条件；不是给人员额外授权的入口 |

一人可以属于多个组，秘密或机密文档只归属一个知悉组；只要文档所属组在人员有效组集合中，知悉范围条件就满足。还必须同时满足密级要求。

负责人用于责任归属，不会自动加入组或获得文档权限；需要阅读组内资料时仍须显式配置成员及人员密级。用户组可以按当前筛选条件导出 Excel，旧版组密级不作为授权或导出口径。

停用组不计入有效知悉范围，也不继续传递组策略；人员原归属关系保留，避免停用、恢复过程中无意丢失成员。组被人员、策略绑定或文档引用时，不能直接删除。

策略与适用对象放在同一维护流程。“绑定用户组”表示将限制批量应用于该组成员；不是把文档自动改成这个组，也不是把人员提升到某个密级。文档范围由策略选择的密级确定。

例如，对项目A组绑定“秘密资料09:00—18:00访问”后，组成员访问秘密级资料要满足这个时段，同时仍要具有该文档所属组资格。跨日值班可以配置20:00—08:00。多条生效限制叠加，必须同时满足，不用另一条“允许”覆盖拒绝。管理员被明确绑定限制时也执行限制。

当前已有12条常用时间场景供选择；它们初始不绑定人员或组，只有配置有效适用对象后才会参与对应人员的判断。旧允许配置保留历史，不作为新增文档授权依据。

### 审计告警中心

| 页面 | 记录什么 | 应如何理解 |
| --- | --- | --- |
| RAG审计日志 | 检索身份、准入决定、执行结果、过滤与拦截明细、耗时 | 回答“谁查了什么、请求是否执行、哪些文档为什么被拦截” |
| RAG行为告警 | 从审计中识别权限违规、敏感查询、风险、频次、重复查询及慢查询等事件 | 回答“哪些行为需要人工核查和处置” |
| 访问监控 | 平台接口路径、请求方式、来源、耗时及处理结果 | 定位接口错误和操作问题；不等同于文档授权审计 |

“请求拒绝”“请求获准但部分文档被拦截”“请求获准但下游执行失败”必须区分。不能为了增加拒绝数量而制造假日志；可以筛选真实拒绝记录并查看原因。

告警可确认或忽略；涉及限制人员时须明确处置动作及说明。“标记高风险”不等同于封禁，临时封禁也不等同于停用登录账号。重复提交旧处置表单会被拒绝，避免覆盖已经发生的处置。

Excel用于筛选后的表格交付。检索审计和告警均有独立的 Syslog 摘要；审计 Syslog 导出按筛选范围生成，不受列表页码影响，单次超过2000条会明确要求缩小范围。默认网络摘要不含查询正文，消息带编号便于回到平台追溯。网络写入完成不等于对方已经保存；平台数据库中的原始审计仍是本地追溯依据。

### 安全治理中心

IP黑白名单控制请求来源。相同来源同时命中时，沿用当前设计的白名单优先规则；停用规则不再参与判断。来源按服务端可信连接及明确配置的代理边界解析，不能用任意客户端转发头绕过。

行为控制会根据频次、重复查询、失败次数和风险作限制。频次和重复查询中的部分规则采取收缩返回范围的方式，不应介绍成所有超限请求都会被HTTP拒绝。连续失败达到配置规则时可临时锁定知识访问。

### 系统管理与运维

| 内容 | 作用 | 与知识访问的边界 |
| --- | --- | --- |
| 用户、角色、菜单 | 管理账号和平台功能权限 | 能进入管理页面，不代表能阅读所有知识文档 |
| 部门、岗位 | 维护组织和岗位资料 | 不自动成为文档知悉组 |
| 字典、参数、公告 | 维护公共配置及平台通知 | 不用于绕过密级和组判断 |
| 操作日志、登录日志 | 追踪管理操作和登录事件 | 与检索审计分工明确 |
| 在线用户、任务、服务监控 | 查看运行状态及运维任务 | 仅管理侧使用，不向普通用户门户暴露 |

开发辅助的代码生成、表单构建及接口文档不能当作权限控制业务成果介绍；生产交付时应按实际运维需求收紧暴露范围。

### 普通用户门户

普通用户只使用知识查询、本人访问范围说明和本人文件管理，不查看平台管理信息。用户可以上传文件；上传人取当前登录身份，秘密或机密资料只能选择本人有效知悉组，文档密级不能超出本人允许的级别。

“我的文件”按上传人限定；能管理本人文件，不代表其正文不受访问规则限制。普通用户不能修改文档编号、冒充其他上传人，不能把已归档文件自行恢复启用。平台管理侧可以追踪上传人及相关文档、审计和告警。

## 三、一条请求如何走完

1. 用户登录，平台验证当前账号与会话。
2. 核对可信来源、人员知识访问状态、时间和行为限制。
3. 加载当前人员密级、有效组和绑定策略，生成检索约束。
4. 调用向量检索，并传入密级、知悉范围和状态约束。
5. 按最新平台标签复核候选；不满足的文档保留拦截依据，不把正文返回普通用户。
6. 保存请求审计，触发行为分析；已形成告警的事件进入处置流程。
7. 普通用户得到授权结果；管理员在平台查看审计与原因，按需导出或对接日志系统。

介绍时可用一句话串联：“身份管理确定人，文档标签确定资料范围，策略限定访问条件，检索前后双重过滤保证返回边界，审计告警形成事后追溯与处置。”

## 四、应如实说明的交付边界

平台权限判断与语义模型能力分别验收。正式嵌入模型、回答服务、OCR弱版式优化，以及内部文件服务认证、向量标签同步和上传超时结果确认，仍需与对应服务负责人联调。不能把目前过渡向量当作正式语义检索，也不能用原生Word/OFD正文读取结果代替扫描文件OCR精度。

已确认采用“人员密级＋知悉组”模型，替代早期文档中的组员最低密级继承方案。工作时段通过实际配置和绑定生效，当前并未擅自给所有人员新增全局限制。若现场要求“所有秘密及机密资料统一限定工作时间”，应先确认统一时间和适用范围，再作为明确配置实施。

性能已验证本地小数据集下固定预热后的100并发；冷态、正式模型和目标部署环境须单列验证。异常识别的合成规则样本通过不代替甲方真实业务样本指标。没有指定国标编号、等级和测评范围时，不应承诺已取得相应符合性结论。
