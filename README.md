# 向量库访问控制平台

基于 RuoYi-Vue 的身份权限与知识访问控制平台，包含管理端和普通用户知识门户。平台功能与业务流程见 [功能说明](doc/platform-overview.md)，当前验证结果见 [本轮记录](doc/acceptance-20261030.md)，前一轮结果见 [历史记录](doc/acceptance-20261029.md)。正式语义嵌入、回答模型与跨服务一致性仍有待联调，当前版本不代表整套 RAG 系统已完成最终验收。

## 核心业务规则

| 文档类别 | 访问资格 |
| --- | --- |
| 公开 | 不要求人员密级和知悉用户组 |
| 内部 | 人员密级达到内部级或更高 |
| 秘密、机密 | 人员密级满足要求，且文档唯一知悉组属于人员所在的有效组集合 |

人员可以加入多个组，用户组只表示知悉范围。部门、平台角色与人员密级分别维护，管理员身份不代表拥有全部文档访问权限。人员状态、文档状态、个人访问时间、风险控制与已绑定的附加策略仍须通过校验。

附加时间策略支持自定义日间或跨日时段，可作用于全部文档或所选密级。组绑定将策略应用于组成员，文档范围由策略所选密级确定。多条限制叠加执行，不扩大基础访问资格；被明确绑定策略的管理员也遵守相应限制。日期时间按服务端配置时区解释。

## 平台功能

- 人员资料、密级、知悉组及角色维护，人员权限统一保存。
- 用户组负责人、成员与状态维护，停用组不参与有效知悉范围与组策略传递；存在引用时保护删除。负责人用于责任归属，不自动取得成员身份或文档权限。
- 策略、适用对象及版本记录，服务端验证条件并在事务内保存。
- 文件上传、上传人追踪、本人文件列表、文档标签与启停管理。
- 检索前权限约束、候选结果逐条复核及普通用户响应字段隔离。
- 请求审计、执行状态区分、行为告警处置、访问监控与真实 Excel 导出。
- 临时导出文件的归属验证与过期清理、IP 黑白名单，以及检索审计和告警摘要的 Syslog 导出与转发。

文件原件、元数据与向量切块分别由对象存储、MariaDB 和 Milvus 保存。停用不会物理删除原件或向量；完整物理删除与回收流程尚未提供。

## 运行与迁移

本轮验证使用平台 Java 8、文件服务 Java 17，前端生产构建使用 Node.js 24.11.1。本机实际数据库为 MariaDB 12.3.2，并在 MariaDB 10.11 隔离实例完成了逻辑恢复验证；同时使用 Redis、MinIO 和 Milvus。平台端口为 8080，文件服务为 8081，前端为 1024。依赖与连接配置分别在各模块的配置文件中。

分别使用对应 Java 环境构建和启动两个后端：

```bash
mvn -pl ruoyi-admin -am -DskipTests clean package
java -jar ruoyi-admin/target/ruoyi-admin.jar
```

文件服务的启动方式见 [RAG Server 说明](rag_server/README.md)。前端在 `ruoyi-ui` 目录安装锁定依赖后执行 `npm run dev`，访问 `http://localhost:1024`。本地容器配置为 `docker-compose.rag.yml`；已有数据卷不会自动重放初始化脚本。当前开发运行使用本机原生数据库和 Redis，容器编排中的数据库及缓存端口与实际应用连接不同，不能直接将容器默认库当作现有平台数据源或恢复目标。新环境需要先统一连接配置和数据迁移方案。

既有数据库先备份，并核对已执行的历史迁移。本轮迁移为：

1. `sql/add_rag_audit_query_indexes_20261029.sql`：审计频次与重复查询的组合索引。先检查同名索引定义，适用于本轮 MariaDB 环境。
2. `sql/add_access_time_scenarios_20261029.sql`：12 条常用时间策略及首次版本记录。需先完成历史策略版本表迁移；不覆盖既有同编码策略，不添加人员或用户组绑定。
3. `sql/add_group_manager_20261030.sql`：新增可空的用户组负责人编号。升级到本轮服务前先执行，保留原有组及成员关系，不自动指定负责人。

本地开发配置和示例账号不能直接作为生产部署配置。部署前须替换开发凭据、限制内部服务和数据服务的网络访问，并完成目标环境的备份恢复与联调验证。共享存储的持久化与跨存储恢复尚未完成部署验收，不能仅保留部分数据卷就认定知识库可以完整恢复。

## 当前边界

当前检索链路能调用 Milvus，并实施前后两阶段权限过滤；现有向量生成仍为过渡实现，正式语义嵌入与回答服务尚未完成集成。向量标签同步、上传结果确认及 OCR 弱版式质量仍需补齐。性能数据仅覆盖记录中的本地数据量与协议，接入正式模型或改变部署环境后须重新验证受影响项。
